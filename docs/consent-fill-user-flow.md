**ทำไมต้องเสียบบัตร (ด.1.1.1)** — ที่นี่ *เจ้าหน้าที่* เป็นคนเปิดฟอร์มให้จากทะเบียน
ผู้รับบริการ ระบบจึงต้องพิสูจน์ก่อนว่าเจ้าของข้อมูลอยู่ตรงหน้าจริง ไม่ใช่การกรอกแทน
โดยไม่มีเจ้าตัว

| เหตุการณ์ | พฤติกรรม | สถานะ |
|---|---|---|
| กด ‹ ตอนอยู่หน้าเสียบบัตร | กลับไป popup เลือกใบทันที (ยังไม่มีอะไรให้ทิ้ง) | ✅ |
| กด ‹ / ✕ หลังกรอกไปบางส่วน | AlertDialog เตือน "ย้อนกลับไปเลือกแบบฟอร์ม?" / "ละทิ้งการกรอกแบบฟอร์ม?" | ✅ |
| เปลี่ยนใบ (‹ แล้วเลือกใบใหม่) | ต้องเสียบบัตรใหม่ทุกครั้ง — การยืนยันไม่ค้างข้ามใบ | ✅ |
| ผู้รับบริการไม่ได้นำบัตรมา | หน้าเสียบบัตรมีหมายเหตุให้ใช้ช่องทางอื่น (บันทึกจากเอกสาร ด.1.1.8 / ผู้แทนโดยชอบธรรม) | ✅ ข้อความ · 📋 ยังไม่มีปุ่มลัดไปช่องทางนั้น |
| อ่านบัตรไม่สำเร็จ / ดึงบัตรออกกลางคัน | ควรขึ้น error + ปุ่ม "อ่านบัตรอีกครั้ง" | 📋 mock ปัจจุบันสำเร็จเสมอ |
| ข้อมูลหน้าบัตร ≠ ผู้รับบริการที่เลือก | ควร block + แจ้งว่าเป็นคนละคน | 📋 รอ backend เครื่องอ่านบัตรจริง |

## 3 · ระบบงานเวชระเบียน — ตรวจก่อนว่าเคยเสียบบัตรหรือยัง 📋

> **ยังไม่ทำใน vibe code** (คำสั่ง user 14 ส.ค. 2569) — ตอนนี้กดการ์ดแล้วเข้าฟอร์มตรง
> เพราะเคสหลักคือผู้รับบริการเสียบบัตรมาแล้วที่ตู้ Kiosk ก่อนถึงเคาน์เตอร์

กติกาที่ต้องทำเมื่อทำจริง:

```
กด "กรอกแบบฟอร์ม" บนการ์ด (Step 1)
        │
        ▼
  ┌───────────────────────────────────────────┐
  │ เคยยืนยันตัวตนด้วยบัตรประชาชนใน visit นี้? │
  └───────────┬───────────────────┬───────────┘
              │ เคย               │ ยังไม่เคย
              ▼                   ▼
     ╔═════════════════╗   ╔═══════════════════════╗
     ║ popup กรอกฟอร์ม ║   ║ ⓘ เสียบบัตรประชาชนก่อน ║
     ║ (ข้ามขั้นบัตร)   ║   ╚═══════════┬═══════════╝
     ╚═════════════════╝               ▼
                              ╔═══════════════════════╗
                              ║ popup กรอกฟอร์ม       ║
                              ╚═══════════════════════╝
```

**"เคยเสียบบัตร" นับจากอะไร** (ต้องเคาะกับ backend ตอนต่อจริง):

1. เสียบบัตรที่ **ตู้ Kiosk** ตอนเช็คอิน (`bma.kiosk` ขั้น 02-InsertIdCard → 03-Verifying)
2. กด **"อ่านบัตรสมาร์ทการ์ด"** บนหน้าลงทะเบียน (ปุ่มมีอยู่แล้วใน SubHeader)
3. ยืนยันตัวตนด้วยบัตรในระบบจัดการความยินยอมของ visit เดียวกัน

ทั้งสามทางควรเขียนธงเดียวกันลง visit/session เช่น
`idCardVerifiedAt` + `idCardVerifiedBy` (kiosk / counter / consent) แล้วให้ฝั่ง UI
อ่านธงนั้นตัวเดียว — ไม่ใช่ต่างที่ต่างจำ

**อายุของการยืนยัน**: ผูกกับ visit ปัจจุบัน (เช็คอินรอบนี้) ไม่ใช่ตลอดไป — ข้าม visit
ต้องเสียบใหม่

**ตัวเปิด/ปิดใน UI ที่มีอยู่แล้ว**: `ConsentDisclosureFillPopup` รับ prop
`requireIdCard` (default `false`) — ระบบจัดการความยินยอมส่ง `requireIdCard` ตรง ๆ
ส่วนเวชระเบียนจะเปลี่ยนเป็น `requireIdCard={!idCardVerifiedAt}` เมื่อมีธงจริง
**ไม่ต้องแก้ตัว popup**

## 4 · หลังกรอกเสร็จ (เหมือนกันทุกทางเข้า)

```
กด "บันทึก"
   │
   ├─ ทุก clause ตอบ "ยินยอม"      → outcome = signed   → record สถานะ "ยินยอมแล้ว"
   └─ มีอย่างน้อย 1 clause "ไม่ยินยอม" → outcome = declined → record สถานะ "ปฏิเสธ"
   │
   ▼
recordMrConsentSigning({ hn, name, formId, formTitle, type, version, channel, outcome })
   │
   ├─ มีคำขอ "รอลงนาม" ของหัวข้อนี้ค้างอยู่ → อัปเดตฉบับนั้น (ไม่สร้างซ้ำ)
   ├─ มีฉบับ ยินยอมแล้ว/ปฏิเสธ อยู่แล้ว     → อัปเดตฉบับเดิม + ต่อ history
   └─ ไม่มีเลย                              → สร้าง record ใหม่
   │
   ▼
ฝั่งที่เรียกทำต่อเอง:
   • /consent            → ปิด popup ทั้งกอง + toast + ตารางอัปเดตสด (subscribe store)
   • เวชระเบียน Step 1   → ติ๊ก consentCompletedIds + markRegistrationConsentCompleted → การ์ดหาย
   • หน้าเต็ม            → history.push กลับ returnTo (/registration/register หรือ /consent)
```
