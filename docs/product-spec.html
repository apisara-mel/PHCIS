3Cross-cutting Patterns

3.1 StepProgress check-mark rule

Component: StepProgress.jsx. A step circle renders in one of three types:

TypeVisualWhen
currentbrand-filled circle, 4-px outer ring, bold titleidx === current (always wins)
successbrand-filled circle, animated checkcompletedSteps[idx] === true (or idx < current when prop omitted)
defaultneutral filled circle with step numberotherwise

The completedSteps prop is the opt-in validation gate (StepProgress.jsx:213-237): a step earns ✓ only when its required fields are filled — not just because the user advanced past. Parents compute the array; the component never validates on its own.

Per-form validators:

  • Registration → getRegistrationCompletedSteps(form) in registrationForm.js — array of 5 booleans, derived from <Field required> markers.
  • Treatment → getTreatmentCompletedSteps(form, stepIndex) in treatmentVisits.js — array of 7 booleans. Steps 1, 2, 3, 5 use advance-past semantics; 4, 6, 7 use real validators.
  • OPD Screening → inline from stepValidities[idx]. Step bodies opt in by calling onValidityChange(boolean).

3.2 Dirty tracking + unsaved-changes guard

Pattern lives most fully in ScreeningPage.jsx:823-921.

  • dirtyStepsRef (ref) + dirtySteps (state mirror) — per-step Set of touched steps.
  • markDirty listens to onKeyDown + onPointerDown on the form wrapper — NOT onChange / onInput, because autofill / library dispatchEvent fires those. Gates on event.isTrusted and on aria-pressed / aria-label="decrement|increment" for pointer presses, so only real user gestures flip the flag.
  • Save-draft button visible always; disabled when !anyDirty so clicking doesn't persist an empty draft.
  • Next button disabled until currentStepValid. Validity = stepValidities[current] ?? currentStepDirty — explicit wins over heuristic.
  • Unsaved-changes popup fires from handleBack when dirtyStepsRef.current.size > 0. Outcomes: save-draft + leave / discard + leave / cancel.

3.4 Voice + AI inputs

  • SuggestibleTextarea — textarea with mic + language toggle + typing suggestions. Used pervasively. Every voice textarea in this project must ship with suggestions + minChars — bare VoiceTextarea is forbidden.
  • AISearch / Doctor AI — powers Treatment Step 4's ICD-10 lookup (icdQuery state). DEFAULT / FOCUSED / FILLED visual states with brand-tinted borders.
  • Helpers: speechRecognition.js wraps SpeechRecognition / webkitSpeechRecognition and requests mic permission via getUserMedia before starting recognition.
HTTPS requirement: SpeechRecognition and getUserMedia(audio) require a secure context. Plain HTTP over LAN works for camera via <input capture> but does not work for voice.

3.5 Camera flow

Hook: useTakePhotoCapture. Two branches:

  • Mobile → <input type='file' capture> opens the OS camera app. No HTTPS needed.
  • Desktop → CameraCapturePopup with getUserMedia + device picker. Auto-prefers phone-like devices (Continuity Camera, USB phone, DroidCam) via pickPreferredVideoDeviceId.
  • In-app browsers (LINE / Facebook / Instagram) → detected by prefersInPageCameraPopup. Falls back to the in-page popup since <input capture> is unreliable there.

3.6 Smart card chip read (Registration only)

Trigger: "อ่านบัตรสมาร์ทการ์ด" CTA in the Registration sub-header. Handler: applySmartCardRead(form, patient) in registrationForm.js:301 — merges chip-sourced fields, then re-applies user-typed values for keys the chip does NOT carry: NON_CHIP_FIELDS = ['education', 'occupation', 'marital'].

Chip read locks card-sourced fields (disabled={fromChip}) until cleared.

3.7 PatientCard sticky behaviour

When PatientCard's sticky prop is set, it mounts an IntersectionObserver sentinel + sticky wrapper. On scroll under the app header, the card collapses to a compact "mini" layout (fullName + insurance pill only). Used by TreatmentFormPage and ScreeningPage.

3.8 Step transition animation

Module: stepTransition.js. useStepDirection(stepIndex) tracks forward / backward direction so the wrapper sets data-direction and the CSS keyframe slides content from the corresponding side. The wrapper key={stepIndex} re-mount is what triggers the animation.

3.9 Component Guidelines (Do / Don't)

All 118 routed components in the Components Library carry a <Guidelines> panel — three arrays summarising:

  • behavior — semantic / accessibility contract, state resolution rules, ARIA wiring, project-specific tech gotchas (HTTPS for voice, chrome-stripping rule, etc.).
  • dos — when + why to use, common pairings, recommended sizes / variants per context.
  • donts — anti-patterns from real incidents (bare VoiceTextarea rule, missing aria-label on icon buttons), and confusable alternatives.

Where to read:

  • Live viewer: docs/design-system.html → pick a component → Live tab → Guidelines panel at the bottom of the Section.
  • Canonical source: ComponentsLibraryPage.jsx. Each demo ends with <Guidelines behavior={[…]} dos={[…]} donts={[…]} /> inside its Section.
Where NOT to read: design.md. The token document is intentionally token-only — Guidelines live next to the live demo so they update with the same review as code changes.

4Dashboard

Purpose. Single-page hospital overview + clinical analytics. Lands on / for any logged-in user, surfaces yearly KPIs and 14+ pre-built chart cards (population pyramid, top-10 diseases, NCD control gauges, etc.). Read-only.

Routes: /, /dashboard → DashboardPage.

Page structure

  1. Year selector (Dropdown — defaults to ปีงบประมาณ 2569).
  2. Hospital Overview banner — 6 KPI cards: ประชากร / เกิด / เสียชีวิต / การรับบริการสะสม / ค่าบริการสะสม / หน่วยบริการ. Rendered via SummaryCardsBar variant banner.
  3. Big chart cards — PopulationPyramidCard, OpdTypeLineCard, ResidencePieCard, ServiceCenterMapCard (Leaflet map).
  4. Standard cards — top-10 diseases, visit totals, age-service pyramid, rights donut, monthly visits, disease-21 groups, DM/HT new patients, DM/HT control gauges, working-age groups, COC, consent rate, DM complications. All from DashboardCards.jsx.
  5. Recent patients table — mock list of last few visits.

Data shape. Year-pinned mock values per chart card. No live API.

Pitfall: Leaflet CSS and JS are loaded from CDN with SRI integrity in index.html — if upstream files drift, the map silently breaks.

4.1 Logic

  • Entry: any authenticated route hit on / lands here. Sidebar dashboard key is highlighted by Sidebar derivation when pathname.startsWith('/dashboard').
  • State scope: local to the page — selectedYear (Dropdown) is the only UI state. Nothing persists across sessions.
  • Filter logic: selectedYear is presentational right now — chart cards use internal DEFAULT_* mocks regardless. Wiring a real filter would lift year into a context, thread { year } into every chart data fetcher, and memoise the query keys.
  • No leave-guard / no dirty tracking — page is read-only.
  • Cross-system entry points: the "Recent patients" table rows are mock — they do NOT navigate. Production would route each row to /treat/record or /opd/screening with state: { hn }.
  • Error handling: chart primitives swallow missing data and render an empty state. Leaflet (ServiceCenterMapCard) silently fails on a CDN SRI drift — no fallback UI.

5.3 Logic

Queue → Screening transition

  1. Queue row click → <Link state={{ hn, queue, name }}>.
  2. Patient resolution: getPatientByHN(hn) → fall back to getPatientByShortName(name) → final fallback DEFAULT_PATIENT. Direct visits without router state still render — they get the default profile.
  3. ScreeningConfirmPopup mounts immediately. Cancel → /opd/queue. Confirm → form mounts.

Per-step state model

  • current (0..4) — currently visible step. goNext = () => setCurrent(c => Math.min(STEPS.length - 1, c + 1)).
  • dirtyStepsRef (Set) + mirror state — tracked per step via markDirty. Source-of-truth is the ref so the leave-guard reads synchronously.
  • stepValidities — written by step bodies via onValidityChange. Two-tier Next-button gate: stepValidities[current] ?? currentStepDirty — explicit validity wins.

markDirty event-source filter (deliberate)

  • Listens on onKeyDown + onPointerDown only — NOT onChange / onInput. Autofill, programmatic dispatchEvent, and React strict-mode artefacts fire change/input but not keydown/pointerdown.
  • event.isTrusted rejects synthetic events.
  • Pointer presses additionally require [aria-pressed] (chip toggles) or [aria-label="decrement|increment"] (Stepper +/-) so voice mic / accordion clicks don't flip dirty.

Save Draft

  1. Click บันทึกร่าง (enabled when anyDirty).
  2. saveOpdScreeningDraft({ hn, name, queue }) writes queue|hn|name into sessionStorage under mih:opd-screening-drafts (de-duped via Set).
  3. clearDirty() resets ref + mirror.
  4. history.push('/opd/queue', { activeTab: 'progress', focusDrafts: true }) — back to queue with the "ที่ร่างไว้" tab focused.

Leave guard

handleBack checks dirtyStepsRef.current.size > 0. If dirty → opens UnsavedChangesPopup (save-draft / discard / cancel). If no dirty steps → leaveScreen(): history.length > 1 ? goBack() : push('/opd/queue').

Bed selection branch

Symptom step "เตียง" tag opens BedSelectionPopup. selectedBedId is local. Confirm writes formatThaiBedChipLabel(bedId) onto the tag — the bed becomes part of the symptom slice (not a separate field).

Voice/AI gating (HTTPS prerequisite)

Step 2/3/4 host SuggestibleTextarea voice and AISearch. SpeechRecognition + getUserMedia require a secure context. Over plain HTTP/LAN the mic button silently does nothing — there is no in-app warning.

6.3 Logic

Entry + state ownership

  • Queue row → /registration/register with state: { hn, ... }. RegistrationFormPage resolves patient via findMrPatientByHn(hn) → falls back to DEFAULT_MR_PATIENT.
  • form state lives on the page; each <Field> writes via setForm(s => ({ ...s, [key]: v })).
  • stepIndex is page-local. No URL-driven step routing — refreshing returns to step 0.

Smart-card chip-read flow

  1. User clicks อ่านบัตรสมาร์ทการ์ด in the SubHeader.
  2. handleReadSmartCard calls applySmartCardRead(form, patient).
  3. buildPersonalDataFromPatient(patient) returns chip-sourced fields; NON_CHIP_FIELDS = ['education', 'occupation', 'marital'] are RESTORED from prior typing so chip read never clobbers manual entry.
  4. idCardFromChip set to true → 8 card-sourced fields lock via disabled={fromChip}.
  5. setStepIndex(0) — return to Step 1 so the user can verify chip data.

Step 2 — address mirror logic

  • "เหมือนที่อยู่ตามทะเบียนบ้าน" state in form.useRegisteredForCurrent / useRegisteredForContact.
  • Checkbox disabled until isRegisteredAddressComplete(form.addressRegistered) — gates on zip + province + district.
  • Toggling ON: copyRegisteredInto(...) mirrors text fields. Map pin (lat/lng/pinSaved) stays on target slice.
  • While flag true, a useEffect re-mirrors edits made on addressRegistered.
  • If registered address is later cleared past required keys → both mirror flags drop to false (defense against orphaned data).

Step 3 — emergency contact array

  • form.emergency[] — "เพิ่มผู้ติดต่อ" gated by isEmergencyContactComplete(lastEmergencyEntry).
  • Per-step ✓ requires at least one entry with { name, last, relation, phone } filled.

Step 4 — rights lookup state machine

[empty]  rightsLookupDone === false
     │
     │  RightsLookupPanel: search / lookup
     ▼
[results]  rightsLookupDone === true, rightsGroups = [...buildMockRightsGroups()]
     │
     │  add documents / photos / reorder priorityItems
     ▼
[edited]  same rightsGroups[].documents/photos modified

Step ✓ flips as soon as rightsLookupDone === true. Document / photo uploads are optional.

Step 5 — mobility "อื่นๆ" branch

  • form.mobility is the radio value (walk / wheelchair / cane / assisted / other).
  • When set to other, a mobilityOther Voice Textarea appears with MOBILITY_OTHER_SUGGESTIONS.
  • Step ✓ requires mobility set AND (if other) mobilityOther non-empty.
  • Switching away from other clears mobilityOther so stale text doesn't persist.

Step ✓ aggregation

getRegistrationCompletedSteps(form) returns a 5-boolean array passed to <FormShell completedSteps={...} /> → <StepProgress>.

Missing leave guard: Unlike OPD Screening, Registration does NOT currently implement an UnsavedChangesPopup — back-button via handleBack would lose unsaved work. Parity with OPD is on the to-do.

7.3 Logic

Entry + state ownership

  • Queue row → /treat/record with state: { hn, queue, name }. Page resolves two patient shapes:
    • patient via findMrPatientByHn (MR shape — full address, rights, drugAllergies, chronicDiseases). Used by Step bodies.
    • cardPatient via getPatientByHN (display shape — fullName, englishName, insurance, patientType). Used by the sticky PatientCard header.
  • Both fall back to defaults so direct visits don't crash.
  • form state lives on the page; buildInitialForm(patient) runs once on mount. Switching patients via QueueSubMenu (onPickPatient) calls history.push('/treat/record', { state: { hn, queue, name } }) — the page re-mounts via route param change, so form is rebuilt from the new patient.

Read-only steps (1, 2)

  • Step 1 (ประวัติ) and Step 2 (หน้าจอคัดกรอง) are read-only summaries — no editable fields. They surface upstream data (HistoryTimeline of past visits / nurse-screening summary).
  • getTreatmentCompletedSteps marks these as ✓ once stepIndex > N (advance-past semantics) — there's nothing to validate.

Cross-step linking (4 ↔ 3, 7 ↔ 4)

  • Step 4 → Step 3 "ตรวจร่างกาย" CTA: when Step 4 paints its empty state (no body markers/drawings yet), the empty-state block renders a button that calls onStepChange(STEP_EXAM_INDEX) — sends the doctor back to Step 3 to capture the exam before diagnosing.
  • Step 7 reads Step 4: Cert section computes hasDiagnosisData = Boolean(primaryDx || form.diagnosisNote || form.diagnoses.length). If false, the cert shows "บันทึกการวินิจฉัย" CTA back to Step 4. The cert never copies diagnosis data — it always reads live from form.

Step 5 — order category tabs

  • form.orderCategory is the active tab ('medication' | 'lab' | 'xray' | 'procedure' | 'consult').
  • Each category has its own array (form.medications, form.labs, etc.) — switching the tab does NOT reset, so the user can build orders across categories.
  • Empty-state branch hides the cross-class allergy warning panel; populated-state shows it (dismissible — setForm(s => ({ ...s, showAllergyAlert: false }))).

Step 6 — appointment mode state machine

[undefined]  appointment.mode === undefined

Sticky PatientCard collapse

  • PatientCard is rendered ABOVE TreatmentFormShell with the sticky prop. It owns an IntersectionObserver + sentinel internally.
  • As the form column scrolls under the app Header, the card collapses to its compact "mini" variant (§3.7). drugAllergies + chronicDiseases pills stay visible inline in mini state.
  • Requires the form column to be scrollable — if the wrapping <main> doesn't have overflow: auto, the sentinel never crosses and the mini state never engages.

?role=patient chrome strip

FormFillPage reads useLocation().search and parses role. When role === 'patient', the page:

  • Hides the back-to-catalog button.
  • Hides the "เจ้าหน้าที่กรอกแทน" banner.
  • Sidebar collapses to drawer (< md breakpoint detection).

The form schema renders identically — only chrome differs. This way the QR-landed phone view feels patient-owned without a separate page.

Field renderer dispatch

Each field has type ∈ {text, textarea, date, datetime, signature, checkbox, select, radio-4, radio-5, slider-0-10}. FormFillPage maps type → renderer component:

  • Native renderers (text / textarea / date / datetime / checkbox / select) use the bare HTML element with shared fieldStyle.
  • radio-4 / radio-5 map to RADIO_4_OPTIONS / RADIO_5_OPTIONS constants (zero-config).
  • signature mounts an inline canvas.
  • slider-0-10 renders a 0–10 step slider (for pain scales).

Unknown types fall through to a text input (defensive default).

Filter facet generation (mock)

catalogFiltersForForm(form) uses a deterministic hash of slug to assign mock facets (policy / usage / department / creator / formStatus). This means:

  • Filter facets are stable across reloads (same hash → same facet).
  • They're NOT real metadata — production would replace this with form-level fields.
  • Filter UX still works for catalog testing, but values shouldn't be treated as authoritative.

Persistence

There is no persistence for fills — useState on FormFillPage owns the entire form values map. Refreshing loses everything. Production needs a draft autosave per form session.

9.1 Logic

Role → SubRole cascade

  • Changing user.role clears user.subRole automatically — the sub-role catalog is keyed by role. E.g. switching role from doctor → nurse invalidates subRole = 'gp' (doctor-only).
  • SUB_ROLES[role] may be an empty array — in that case the SubRole picker hides.

Feature access matrix logic

  • Each feature in FEATURE_GROUPS declares supportedLevels: Array<'none' | 'view' | 'edit'>.
  • The radio row renders only the supported levels; e.g. a binary-action feature like "ส่ง QR" only shows 'none' | 'edit' (no 'view').
  • user.features[featureKey] defaults to undefined → renders as "ไม่มีสิทธิ์" (none).

countAccess(user) helper

countAccess(user) → returns { none, view, edit } counts across the entire feature catalog. Used in the user-list table to show a per-row "X features · Y view · Z edit" summary at-a-glance.

Create vs Edit branch

  • /users/new → getUserById('new') returns undefined → BLANK_USER seeds the form.
  • /users/:id → getUserById(id) returns the user or undefined; undefined falls back to BLANK_USER (defensive — should ideally 404).
  • Save / Apply is currently a stub — no persistence wiring. Production needs API integration.

Status toggle

user.status ∈ {'active', 'inactive'}. Inactive users render greyed in the list and are filtered out of role-based permission resolution at runtime (intended; not yet enforced in mocks).

12Pitfalls & Gotchas

React 17 only: React-18 hooks (useId, useSyncExternalStore, etc.) crash at render. See memory note project_react17_runtime.
Voice textareas: every SuggestibleTextarea voice in clinician fields must ship with suggestions + minChars. Bare VoiceTextarea is forbidden. See memory note feedback_voice_textarea_suggestions.
Input chrome stripping: wrapper-owned border/focus chrome → inner native input must strip border / outline / box-shadow / appearance / -webkit-appearance with !important for :focus and :focus-visible. See CLAUDE.md.
Vite host pinning: vite.config.mjs pins host: '127.0.0.1' to avoid a uv_interface_addresses crash with default host. When exposing to LAN, use npx vite --host <ip> to bind to one specific interface (not 0.0.0.0).
Google Drive sync ghosts: vite.config.mjs ignores **/.!* placeholder files + **/.DS_Store in chokidar — without it, the watcher fires on missing files and Vite/Tailwind blow up with ENOENT.
Dirty tracking event sources: on OPD ScreeningPage, markDirty listens on keydown + pointerdown only, gates on event.isTrusted, and for pointer presses additionally requires [aria-pressed] or [aria-label="decrement|increment"]. Prevents autofill + dispatchEvent from flipping the Next-button gate before a real user gesture.
Continuity Camera labels: cameraDevice.js hints include 'continuity', 'iphone', 'desk view', 'continuity camera'. New phone vendors must be added to PHONE_LABEL_HINTS to be auto-picked.
sessionStorage scope: OPD drafts persist only for the tab session, not across browser restarts. Production needs a real backend hook. The key (mih:opd-screening-drafts) is a flat list of queue|hn|name strings — adding fields needs migration logic.
Three identity rosters: mock patients live in three overlapping rosters — PATIENT_PROFILES (display), MR_PATIENTS (registration), TREATMENT_QUEUE_ROWS (queue). Adding a new mock patient requires adding to all three or downstream pages fall back to defaults.
Thai Buddhist dates: DOB / ID issue / ID expiry use formatThaiBuddhistDate / parseThaiBuddhistDate. Format: "20 กุมภาพันธ์ 2563". Parser is strict — month names must match THAI_MONTHS exactly.
National ID mask: formatNationalId(value) injects 1-####-##-###-###. Raw can be 17 chars (13 digits + 4 dashes).
Chip-read NON_CHIP_FIELDS: the Thai ID chip does not carry education, occupation, marital. applySmartCardRead preserves what the user already typed for these three keys.
"อื่นๆ" branches: Mobility 'other' (Step 5 Registration) — mobilityOther must be non-empty for the step to count as complete. Mirror this pattern when adding any new "อื่นๆ" sub-text field.
caption2 token is NOT a duplicate of caption1: An old version of design.md had caption1 and caption2 with identical 12 px values and one got deleted — Figma 3465:2 actually defines caption2 as 10 px. The fix re-numbered the 10 px token from caption3 → caption2 (2026-05-22). If you see code referencing caption3, it's stale.
Effect Styles audit (Figma 3446:4426): Synced 2026-05-22. Brand Inner Shadow 100–600 values rewritten to match Figma's progressive blur (2→16 px) / y-offset (1→12) / α (8%→22%); Blur radii corrected (overlay 4→8 px · layer 4→6 · glass 4→12); Indigo Drop Shadow Bottom 100/200 added (base #818CF8); 6 generic effect.drop-shadow.{3xs..lg} tokens removed (never wired into CSS). UTF-8 markdown serving: vite.config.mjs has a utf8MarkdownPlugin middleware that appends ; charset=utf-8 to text/markdown responses. Without it, browsers fall back to Latin-1 → Thai text in .md renders as mojibake (ถ่ายรูป → à¸–à¹‰à¸²à¸¢à¸£à¸¹à¸›). HTML files have in-file <meta charset="UTF-8"> so unaffected.
